# Lumik

A native SwiftUI document workspace for iPhone, iPad, iPhone Duo, and Mac, with a Next.js backend and public landing page (no web sign-in). Apple projects are generated by XcodeGen.

## Implemented

- Groups with extraction instructions, filename templates, and JSON Schema.
- Visual schema editing, including nested objects and arrays; advanced JSON editing; plain-language AI schema drafts with review before applying.
- Native VisionKit document detection and multi-page scanning on supported iPhone/iPad hardware.
- PDF import from Files, Finder, and Open In; HP-produced PDFs can be imported after scanning in HP’s app.
- Private S3-compatible PDF storage; Turso metadata; owner-scoped access on every API.
- AI SDK + Vercel AI Gateway using `openai/gpt-6-luna` for PDF extraction, content-based naming, schema drafting, and agent chat.
- PDF preview, extraction retry, editable extracted data, renaming by hand or with an AI suggestion from the document's context menu, and group ZIP export with a JSON manifest.
- Subgroups inside any group, with PDFs moved between groups, subgroups, and parents from each PDF's menu. A subgroup starts with its parent's fields, so those moves keep extracted data; moving to a group with different fields reads the PDF again and renames it.
- Lumik's message field shows what the chat is about: the open group and PDF, which can be removed, plus any more groups you add from its add menu. These focus Lumik without limiting what it can reach.
- Scanning or importing PDFs from Lumik's add menu. They wait in an Inbox, which appears in the library while it holds documents, and Lumik proposes where to file them, creating groups or subgroups if needed. The whole plan is one proposal, applied all at once.
- Agent and MCP changes are stored as proposals. A dedicated review sheet and native confirmation apply each proposal once.
- Dedicated sheets for editing/deletion, dropdown action menus, overlay operation feedback, mobile haptics, and full-height Mac sheets.
- Adaptive split navigation for larger screens and Duo; iOS 27’s prominent Lumik tab, with a search-role fallback on iOS 26.

## Backend setup

```sh
cd backend
bun install
cp .env.example .env
# Fill in the values described below.
bun run db:migrate
bun run dev
```

For local development, `.env.example` uses a local libSQL file and local PDF directory. Production must use a Turso database and a private S3-compatible bucket. Never configure a public bucket or commit credentials.

| Variable | Purpose |
| --- | --- |
| `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | Turso database connection; local `file:` URL supported |
| `AUTH_ISSUER` | RxLab issuer, normally `https://auth.rxlab.app` |
| `RXLAB_ALLOWED_CLIENT_IDS` | Comma-separated public Apple/MCP OAuth client IDs allowed to call the API |
| `AI_GATEWAY_API_KEY` | Optional API key for local/non-Vercel use; Vercel deployments authenticate automatically with OIDC |
| `AI_MODEL` | Defaults to `openai/gpt-6-luna`; no silent model substitution |
| `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT` | Private object storage; endpoint optional for AWS |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Storage credentials, or use a deployment IAM role |
| `LOCAL_STORAGE_DIR` | Development-only PDF storage; ignored in production |

The existing public OAuth client keeps its registered redirect **`scannerbuddy://oauth/callback`** for sign-in compatibility. Do not reuse Sticker Gen’s client credentials. RxAuthSwift manages the OAuth flow and Keychain token storage. Apple identity-provider sign-in uses the browser flow, so this project does not require a separate native Sign in with Apple entitlement. The backend validates RS256 signature, issuer, expiry, subject, and allowed `client_id`, matching the reference app’s RxLab token convention. The Apple app is a public OAuth client. The backend only verifies bearer tokens using the issuer’s public JWKS; it does not run a web sign-in flow or need an OAuth client secret or Auth.js session secret.

Run `bun run build` and `bun run start` for production. Run migrations before starting the server. The native app requests a ten-minute presigned PUT URL, uploads the PDF directly to private S3-compatible storage, then completes the upload with a small API request. Completion validates size and PDF signature before copying the bytes to a separate final key and starting extraction. Storage credentials need GetObject, PutObject, and DeleteObject access. Run migrations before deploying this flow (it adds `pdf_uploads`). Subgroups and the Inbox also need them (they add `groups.parent_id` and `groups.kind`). Local development with `LOCAL_STORAGE_DIR` uses the authenticated multipart endpoint. Keep function duration at 120 seconds for extraction. Schedule `storage:cleanup` to remove abandoned staging uploads after expiry.

Xcode Debug uses `http://localhost:3000`; Release uses `https://www.lumik.dev`. These URLs take precedence over `Local.xcconfig`. Localhost works for macOS and the iOS Simulator; a physical iPhone needs a separately configured reachable development host.

Deleting a group moves it and its subgroups to the Recycle Bin, where they can be restored together for 30 days. After that, or when it is deleted from the bin, its documents are removed and its PDFs are queued for cleanup in one transaction. Deleting a single document skips the bin. Failed cleanup is retried on later deletes/approvals. Schedule `bun run storage:cleanup` regularly to purge expired groups and drain the queue even when there is no user activity. Keep the storage bucket private throughout.

## Apple app setup

```sh
cp ios/Configuration/Local.xcconfig.example ios/Configuration/Local.xcconfig
# Set DEVELOPMENT_TEAM; optionally override RXLAB_CLIENT_ID and SCANNER_API_URL.
xcodegen generate --spec ios/project.yml
open ios/Lumik.xcodeproj
```

Run the **Lumik** scheme on iPhone/iPad/Duo, or choose **My Mac** as its destination for the native Mac app. One target builds both. Signing uses the development team in `ios/project.yml`; change `DEVELOPMENT_TEAM` there, not in Xcode, because regenerating the project overwrites Xcode edits. Document camera scanning is iOS-only, so on Mac add documents by importing a PDF. Minimum OS is 26, matching RxAuthSwift. Debug and Release use `https://www.lumik.dev`. Authentication uses `https://auth.rxlab.app` in both configurations. The app’s API origin must reach the backend from the device; for physical hardware, override `SCANNER_API_URL` with your Mac’s LAN address in `Local.xcconfig`. That optional file overrides both configurations.

The Debug-only `--ui-preview` launch argument shows a fixture library without connecting to an account. Preview mutations and network requests are deliberately disabled. Release builds ignore it.

## API and MCP

See [backend/openapi.json](backend/openapi.json) for the REST contract; regenerate it with `bun run api:spec`. All document APIs require `Authorization: Bearer <RxLab access token>`; there is no development authentication bypass.

The stateless Streamable HTTP MCP endpoint is **`POST /api/mcp`**, authenticated with the same bearer token. It provides `list_groups`, `list_documents`, `analyze_document`, `propose_change`, and `list_proposals`. Proposed mutations appear in the app’s Lumik tab; MCP cannot approve its own changes. Configure the MCP client to obtain/refresh a valid RxLab token; dynamic OAuth client registration is not implemented.

## Current boundaries

- macOS supports Image Capture-compatible scanners with an automatic document feeder (including supported HP models). In a group, choose **Scan from Scanner** from the actions menu. Set color/grayscale/black-and-white, driver-supported DPI, and duplex in **Scan Settings**. Each feeder stack becomes one PDF; the session waits for the next stack until **Stop**. Review scans, then **Upload Batch**. Successful uploads leave the queue; failed uploads remain for retry. Interrupted documents are marked partial. Unuploaded scans are temporary and discarded when you confirm closing the sheet; they do not survive application termination.
- Duplex and automatic reload detection depend on the scanner’s macOS Image Capture driver. Duplex is enabled by default when advertised; simultaneous front/back capture depends on hardware. Close other scanner apps before connecting. Physical HP scanning still needs on-device validation. Flatbed scanning can be imported from Image Capture as a PDF.
- Live RxLab sign-in, Turso, S3, and AI Gateway require your service configuration; local tests do not establish live provider compatibility or account access.
- Scanning needs supported physical hardware. Simulator builds cannot prove camera detection quality or haptic behavior.
- Group exports currently cap total source PDFs at 100 MB. Individual uploads have no app limit, though a single S3 PUT tops out at 5 GB. Larger archives need a streaming/background export job.
- The filename template names a group's first PDFs. Once it has processed or renamed documents, new PDFs follow the pattern of its 20 most recent names instead, so hand-edited names carry forward and later template edits have no effect until those names change.
- Processing can be retried after a three-minute stale lease. Every upload is extracted and renamed automatically, and the app polls until it finishes; there is no background worker or push completion notification yet. Failed documents can be retried from the document menu, or Lumik can analyze a document and propose its fields for review.
- Metadata refreshes on screen load and pull-to-refresh; offline caching and real-time cross-device updates are not implemented. Chat history is held in memory; pending proposals persist in Turso for 24 hours.

Reference patterns came from `~/Desktop/sticker-gen` (RxLab auth) and `~/Desktop/rxlab/rxcode/RxCodeMobile` (Duo navigation and prominent agent tab). Model and SDK references: [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [AI SDK structured output](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data), [Vercel AI Gateway](https://vercel.com/docs/ai-gateway/models-and-providers).

## Landing page

The public `/` route introduces Lumik with responsive Material-inspired layouts, reduced-motion-aware animation, and generated transparent PNG artwork. Download actions open a native browser dialog. The page checks the latest published GitHub release every five minutes and links to its `Lumik.dmg` asset. Until a release is available, it shows the package version as a release in preparation and links to the release listing. Keep `backend/package.json` version aligned with `ios/project.yml` when updating the unreleased version. iOS download details remain pending until a distribution URL is available.

### Account lifecycle

Run `npm run db:migrate` before deploying account endpoints. `GET /api/v1/account`
returns PDF `usedBytes` (including Recycle Bin), nullable `limitBytes`, and nullable
`deleteAt` in epoch milliseconds. `POST` schedules deletion seven days ahead
(idempotently); `DELETE` cancels before the deadline. Expired accounts are denied
access across authenticated APIs. This deletes Lumik data, not the RxLab identity.

Configure `CRON_SECRET` in Vercel for the daily `/api/cron/accounts` job. It removes
expired account records and queues PDF objects for retryable cleanup; physical
removal occurs on the next successful job after the seven-day deadline. The
`storage:cleanup` script also processes expired accounts. A minimal owner tombstone
prevents existing credentials from recreating a deleted account.

`GET /api/v1/legal/terms` and `/api/v1/legal/privacy` serve Markdown from
`backend/legal`. The bundled text is initial draft copy and requires product/legal
review before publication. Native clients render these documents in dedicated sheets.

### PDF processing choice

The Save PDFs and Upload PDFs sheets offer a remembered Model dropdown:

- **Cloud — Server Model** uses the backend's configured `AI_MODEL` (Vercel OIDC remains supported).
- **Apple Intelligence — On Device** reads PDF text with PDFKit, recognizes scanned pages with Vision, and uses Foundation Models for fields, additional facts, and naming. Previous group filenames inform the name. The server validates fields against the group schema and saves the result without calling cloud AI. PDFs still upload through presigned storage URLs for sync.

Apple Intelligence must be available on the device. Local processing currently rejects inputs beyond its conservative 10,000-byte prompt budget instead of truncating pages or falling back to cloud. Choose Cloud explicitly for larger documents. This choice applies to upload processing; existing server actions such as Extract Again, AI rename, and regrouping still use cloud AI.
